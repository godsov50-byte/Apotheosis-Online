## Thirteen-stage action contract

1. Intent records an actor's request, not trusted outcome text.
2. A structured proposal binds action/rule versions, actor, targets, arguments, expected state version and immutable request ID.
3. Prerequisites derive acquisition, technique graph, mastery, body/tool and affinity conditions.
4. Resource validation checks available AP, per-domain EA, objects, daily limits and committed preparation.
5. Permission validation applies operation-specific authority, consent and scope.
6. Spatial/physical validation establishes actual reach, containment, contact or anchored custody.
7. Applicable modifiers are filtered before arithmetic; none repairs a failed hard gate.
8. Deterministic resolution computes the registered rule on exact inputs.
9. The provisional outcome describes proposed deltas without publishing them as reality.
10. Reconciliation checks expected versions and mechanic-specific invariants/conservation.
11. Commitment changes authoritative local state once.
12. History appends the causal record and hash-chain link.
13. Projection reveals only authorized results, not every internal state field.

## Transaction identity and exploit defense

A repeated request with the same complete payload returns its recorded result; the same ID with altered payload rejects. Concurrent claims on a last use or one corpse recovery serialize so only one can commit. Reconciliation recomputes the expected transition; a forged nonnegative life increase is still rejected rather than accepted by a simple bounds check. Stable aliases and Heirloom IDs prevent identity-reset counters.

Life transactions require committed death evidence, matching Sovereign/body/corpse provenance, explicit policy and actual physical custody. Agent authority requires typed operation-specific preconditions and scope at resolution. These cannot be replaced by a generic client permission set or title. UNKNOWN remains a blocked policy/input, not an instruction for natural-language improvisation.

The model uses in-process locks and hash chains. It does not claim durable atomic commits across databases, authenticated external callers, distributed consensus or rollback recovery after process crashes. Those production requirements remain outside this design implementation.
